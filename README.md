# Связка

Экспедиция продуктовой команды: инструмент CPTO для управления небольшой IT-командой в форме игры. Первая версия — для одного человека, данные лежат локально.

Сейчас готовы три шага: схема данных с загрузчиком и примером; движок, который считает давность контекста, покрытие навыков, нарушения RACI и сигналы хода; и команда `sv`, которая показывает всё это в терминале.

## Запуск

Нужен Node.js 22 или новее.

```bash
npm install
npm run check
```

`check` проверяет типы, прогоняет тесты и валидирует пример данных.

## Папка игры

Состояние игры — папка с Markdown и YAML. Слой видимости задаётся папкой.

```
team/                 видит отряд
  people/<id>.md      кто, роль, тип, ремесло
  agents/<id>.md      агент, кто за него отвечает, его отчёты
  tasks/<id>.md       переход: местность, статус, RACI, разведки
  map.yaml            лагеря, этап цикла, погода
pair/<id>/            человек и CPTO
  sheet.md            состояние, оценки, квест, темы 360
  journal.md          встречи
me/<id>.md            только CPTO: связи, заметки на полях
turns/<дата>.md       ход: внимание, действия, решения, что не успел
config.yaml           срок годности, внимание, модель штурмана
```

Данные в Markdown-файлах лежат в YAML-шапке между строками `---`; ниже шапки можно писать свободные заметки. Файлы удобно править руками, в том числе в Obsidian.

Проверить свою папку:

```bash
npm run validate -- путь/к/папке
```

## Команда sv

```bash
./bin/sv roster --dir examples/demo --today 2026-11-13   # отряд
./bin/sv signals --dir examples/demo --today 2026-11-13  # сигналы хода
./bin/sv raci --dir examples/demo                        # матрица RACI и нарушения
./bin/sv skills --dir examples/demo                      # ремесло по отряду
./bin/sv sheet mark --dir examples/demo                  # лист человека
./bin/sv sheet mark --layer team --dir examples/demo     # тот же лист глазами отряда
```

Без `--dir` берётся папка из переменной `SVYAZKA_DIR` или текущая, без `--today` — сегодняшняя дата.

## Пример

`examples/demo` — вымышленная команда из макетов: пять человек, два агента, шесть переходов. В данных намеренно оставлены нарушения, которые находит линтер: переход, за который отвечает агент; переход, который никто не ведёт; человек, отвечающий за три перехода сразу.
