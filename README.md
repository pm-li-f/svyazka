# Связка

Экспедиция продуктовой команды: инструмент CPTO для управления небольшой IT-командой в форме игры. Первая версия — для одного человека, данные лежат локально.

Сейчас готовы девять шагов: схема данных с загрузчиком и примером; движок, который считает давность контекста, покрытие навыков, нарушения RACI и сигналы; команда `sv`; ход — утренняя отметка внимания, действия, журнал решений и закрытие дня с коммитом; веб-интерфейс с экранами отряда, листа, переходов и хода; карта — экран стратегии, где рельеф строится из состояния игры; штурман — модель, которая отвечает на вопросы по данным игры; игровой слой — заставки и эффекты, которые каждый настраивает или выключает сам; и чтение Jira и Confluence, из которого получаются сигналы.

## Запуск

Подробная пошаговая инструкция для Windows, macOS и Linux — в [docs/kak-zapustit.md](docs/kak-zapustit.md).

Нужен Node.js 22 или новее.

```bash
npm install
npm run check
```

`check` проверяет типы, прогоняет тесты и валидирует пример данных.

## Папка игры

Состояние игры — папка с Markdown и YAML. Слой видимости задаётся папкой.

```
team/                 видит отряд
  people/<id>.md      кто, роль, тип, ремесло
  agents/<id>.md      агент, кто за него отвечает, его отчёты
  tasks/<id>.md       переход: местность, статус, RACI, разведки
  map.yaml            лагеря по порядку маршрута, этап цикла, погода, план состава
pair/<id>/            человек и CPTO
  sheet.md            состояние, оценки, квест, темы 360
  journal.md          встречи
me/<id>.md            только CPTO: связи, заметки на полях
turns/<дата>.md       ход: внимание, действия, решения, что не успел
config.yaml           срок годности, внимание, модель штурмана
```

Данные в Markdown-файлах лежат в YAML-шапке между строками `---`; ниже шапки можно писать свободные заметки. Файлы удобно править руками, в том числе в Obsidian.

Проверить свою папку:

```bash
npm run validate -- путь/к/папке
```

## Команда sv

```bash
./bin/sv roster --dir examples/demo --today 2026-11-13   # отряд
./bin/sv map --dir examples/demo --today 2026-11-13      # карта: маршрут, местность, состав, трещины
./bin/sv signals --dir examples/demo --today 2026-11-13  # сигналы хода
./bin/sv raci --dir examples/demo                        # матрица RACI и нарушения
./bin/sv skills --dir examples/demo                      # ремесло по отряду
./bin/sv sheet mark --dir examples/demo                  # лист человека
./bin/sv sheet mark --layer team --dir examples/demo     # тот же лист глазами отряда
```

Без `--dir` берётся папка из переменной `SVYAZKA_DIR` или текущая, без `--today` — сегодняшняя дата.

## Ход

Ход — один день. Своя папка игры должна быть отдельным git-репозиторием: коммит в конце хода и есть журнал.

```bash
export SVYAZKA_DIR=~/svyazka-game      # своя папка игры
sv turn start                          # сколько сил на сегодня; предложит обычное значение
sv signals                             # на что стоит потратить внимание
sv sheet timur                         # открыть лист: −1, один раз за ход на человека
sv 1on1 timur --note "Разобрали шторм" # −2, обновит дату встречи и журнал
sv decide "Дублёр по billing-db — Тимур, после перевала"
sv turn                                # как идёт ход
sv turn end                            # что не успел, коммит «ход <дата>»
```

Правила внимания: бюджет не выше потолка и не выше обычного плюс запас (оба числа в `config.yaml`); перерасход не запрещён, а показывается; несколько ходов подряд на потолке — сигнал на тебя самого. Цены действий тоже лежат в `config.yaml`.

## Веб-интерфейс

```bash
npm run web -- --dir ~/svyazka-game
```

Откроется на http://127.0.0.1:4173. Экраны: отряд, карта, переходы, лист, ход и настройки. Страница сама перечитывает данные, когда папка игры меняется — из терминала или из Obsidian.

- Сервер слушает только свою машину и не отвечает чужим страницам.
- Открытый лист списывает внимание так же, как в терминале: один раз за ход на человека.
- На листе есть переключатель «чьими глазами смотреть»: отряд, сам человек или ты.
- Параметры: `--port` — другой порт, `--today` — посмотреть состояние на другую дату.

## Карта

Карта — экран стратегии. Её никто не рисует руками: она каждый раз собирается из папки игры, и одно и то же состояние всегда даёт одну и ту же карту.

| На карте | Откуда берётся |
|---|---|
| Маршрут и лагеря | `team/map.yaml`, лагеря по порядку |
| Положение отряда | доля пройденных переходов к цели |
| Тропа, перевал, туман, шторм | открытые переходы и их местность |
| Размер пятна | сколько дней переход открыт |
| Дымка над дальним маршрутом | погода: в forming и storming далеко не видно |
| Состав | люди, агенты, `headcount` из `map.yaml` и роли по Белбину, которых нет |
| Трещины | навык на одном человеке и переходы, которые стоят |

Карта строится только по слою отряда. Исключение — строка «внимание командира»: сколько очков за последние дни ушло на маршрут, а сколько на всё остальное. Работа над маршрутом записывается в ход прямо с экрана карты или командой `sv act route-block`.

## Заставки и эффекты

Игровой слой живёт только в веб-интерфейсе и настраивается на вкладке «настройки».

- **Заставки** — пиксельный кадр, собранный из текущего состояния: хребет повторяет рельеф карты, погода и время суток настоящие, в связке столько фигур, сколько людей в отряде. Чем чаще событие, тем короче: начало и конец хода — 1–2 секунды, шторм и новый участник — 3–4, взятый лагерь — 5–8. Любая клавиша или щелчок пропускает.
- **Эффекты** — короткая отметка в углу, когда что-то действительно закрылось: снят сигнал, у навыка появился дублёр, линтер RACI позеленел, сделан шаг квеста, человек обновил свой лист.
- **Настройки:** заставки — все, только редкие или выключены; эффекты — полные, сдержанные или выключены; звук — отдельно. С начала стоит «только редкие», «сдержанные» и звук выключен. Настройки у каждого свои: они хранятся в браузере, в папку игры не пишутся.
- Системная настройка «уменьшить движение» соблюдается: заставка становится одним неподвижным кадром, эффекты — без искр.
- Событие считается по разнице двух состояний игры, поэтому правка файла в Obsidian даёт тот же эффект, что и кнопка на странице. При открытии страницы ничего не показывается.

Чего нет и не будет: эффектов за потраченное внимание и число 1on1, эффектов на оценках людей и во время шторма, серий и сравнений между людьми.

## Штурман

Штурман отвечает на вопросы по данным игры и готовит заметки к 1on1. Он только читает: в папке игры ничего не меняет.

```bash
sv keys init                              # создать файл ключей в домашней папке
sv keys --check                           # проверить ключи пробным запросом
sv ask "С кем поговорить первым?"         # вопрос по данным игры
sv ask "Что мешает дойти до лагеря?" --model kimi
sv prep timur                             # заметки к 1on1
```

- **Модели** записаны в `config.yaml` под короткими именами; сейчас подключаются Claude и Kimi, напрямую у поставщиков.
- **Ключи** лежат в `~/.svyazka/keys.env` или в переменных окружения `ANTHROPIC_API_KEY` и `MOONSHOT_API_KEY`. В репозитории и в папке игры их нет.
- **Слои.** У каждой модели в настройках есть `layers`: какие слои данных ей можно отправлять. Закрытый слой до модели не доходит, и каждый ответ подписан: какая модель отвечала, какие слои ушли, что она смотрела.
- **Инструменты.** Модель сама берёт нужное: отряд, сигналы, лист человека, переходы, карту, ремесло, агентов, ходы.

Пошагово — в [docs/kak-zapustit.md](docs/kak-zapustit.md), шаг 10.

## Jira и Confluence

Игра читает Jira и Confluence на своих серверах (Data Center) и превращает прочитанное в сигналы. Только чтение: данные запрашиваются одним методом GET.

```bash
sv sources check      # проверить вход на серверы
sv sync               # снять данные и записать снимок в папку игры
sv sources            # что прочитано и насколько это свежо
sv signals            # что из этого следует
```

- **Ссылки вручную.** В игре живут крупные переходы, а не тикеты. Переход ссылается на Jira полем `jira` в своём файле: ключ эпика или задачи, несколько ключей или свой JQL. Страницы Confluence перечислены в `team/artifacts.yaml`.
- **Снимок.** `sv sync` кладёт прочитанное в `team/sources/`. Движок в сеть не ходит и считает по снимку, поэтому игра работает и без VPN. Сроки отсчитываются от даты снимка; старый снимок игра называет старым.
- **Сигналы.** Задачи в работе без движения, просрочка и ожидание других задач; расхождение игры и Jira (в Jira всё закрыто, а переход открыт; работа идёт у человека вне связки); больше трёх задач в работе у одного человека; страницы, которые давно не меняли.
- **Нагрузка — число, а не оценка.** Людей игра по нему не сравнивает и не упорядочивает.
- **Вход.** Логин и пароль пользователя «только чтение» лежат в файле ключей, рядом с ключами моделей. Если сервер не принимает пароль в запросах к API (в Jira 11 это так по умолчанию), игра входит по сессии. Токен, если он появится, важнее пароля.
- **Штурман** этих данных не видит, пока модели в `config.yaml` не дописан список `sources`.

Проверено на подставном сервере, который отвечает по документации Atlassian. На настоящих Jira 11 и Confluence 8.7 игра ещё не запускалась.

Пошагово — в [docs/kak-zapustit.md](docs/kak-zapustit.md), шаг 11.
