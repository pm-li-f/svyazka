# Как запустить «Связку»

Пошагово, без пропусков, для Windows, macOS и Linux. Если ты уверенно живёшь в терминале, хватит раздела «Коротко».

## Коротко

```bash
git clone https://github.com/pm-li-f/svyazka.git
cd svyazka
npm install
npm link                      # команда sv становится доступна отовсюду
sv init ~/svyazka-game        # своя папка игры
sv web --dir ~/svyazka-game   # http://127.0.0.1:4173
```

Нужны Node.js 22 или новее и Git.

## Что получится в конце

- В терминале работает команда `sv`.
- У тебя есть своя папка игры с твоей командой. Это обычные текстовые файлы на твоём компьютере.
- В браузере открывается «Связка» с экранами отряда, карты, переходов, листа и хода.

Всё работает локально. Наружу ничего не отправляется: штурмана и интеграций в этой версии ещё нет.

## Шаг 1. Открой терминал

Терминал — окно, в которое вводят команды текстом. Команду печатаешь или вставляешь, нажимаешь Enter, читаешь ответ.

| Система | Как открыть |
|---|---|
| Windows | Нажми «Пуск», набери `PowerShell`, открой «Windows PowerShell» |
| macOS | Нажми Cmd+Пробел, набери `Terminal`, нажми Enter |
| Linux | Обычно Ctrl+Alt+T или «Терминал» в меню приложений |

Дальше «выполни команду» значит: вставь её в это окно и нажми Enter.

## Шаг 2. Проверь, что установлены Node.js и Git

Выполни по очереди:

```bash
node -v
git --version
```

Что должно получиться:

- `node -v` печатает версию, например `v22.11.0`. Первое число должно быть **22 или больше**.
- `git --version` печатает что-то вроде `git version 2.47.0`. Версия подойдёт любая свежая.

Если вместо версии написано «не найдено», «not recognized» или «command not found», программу нужно установить.

### Установка Node.js

Скачай установщик с https://nodejs.org (кнопка LTS) и пройди его с настройками по умолчанию. Это работает на Windows и macOS.

Если пользуешься менеджером пакетов, можно через него:

| Система | Команда |
|---|---|
| Windows | `winget install OpenJS.NodeJS.LTS` |
| macOS | `brew install node` |
| Linux | Версия из штатного репозитория часто старая. Надёжнее поставить по инструкции со страницы загрузки на nodejs.org |

### Установка Git

| Система | Как |
|---|---|
| Windows | Установщик с https://git-scm.com или `winget install Git.Git` |
| macOS | Выполни `xcode-select --install` и согласись на установку |
| Linux | Debian и Ubuntu: `sudo apt install git`. Fedora: `sudo dnf install git` |

**После установки закрой терминал и открой заново**, иначе он не увидит новые программы. Затем повтори проверку из начала шага.

## Шаг 3. Скачай проект

Выбери, где он будет лежать. Проще всего в домашней папке — терминал открывается именно в ней.

```bash
git clone https://github.com/pm-li-f/svyazka.git
cd svyazka
```

Первая команда создаёт папку `svyazka` и скачивает в неё проект. Вторая переходит в эту папку. Если репозиторий закрытый, Git спросит логин: войди под своей учётной записью GitHub.

Проверка: команда `git status` отвечает `On branch main`.

> Все команды из шагов 4–6 выполняются внутри папки `svyazka`. Если закрыл терминал, открой его снова и выполни `cd svyazka`.

## Шаг 4. Установи зависимости

```bash
npm install
```

Команда скачивает библиотеки, на которых написан проект. Это занимает от полуминуты до нескольких минут. В конце должно быть `added … packages` без строк, начинающихся с `npm error`. Строки `npm warn` — не ошибка.

Теперь убедись, что всё работает:

```bash
npm run check
```

В конце вывода должны быть три вещи:

```
 Test Files  9 passed (9)
      Tests  70 passed (70)
ok  …/examples/demo
```

Числа могут вырасти в новых версиях; важно, чтобы не было слова `failed`.

## Шаг 5. Сделай команду `sv` доступной

```bash
npm link
```

Проверка:

```bash
sv --help
```

Должен появиться список команд, начинающийся со строки `sv — «Связка» в терминале`.

Если не получилось:

- **macOS или Linux, ошибка `EACCES` или `permission denied`.** Выполни `sudo npm link` и введи пароль от компьютера. При вводе пароля символы не показываются — это нормально.
- **Windows, «выполнение сценариев отключено в этой системе».** Выполни один раз `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`, ответь `Y` и повтори `sv --help`.
- **Команда `sv` не найдена.** Закрой терминал, открой заново, вернись в папку `cd svyazka` и повтори.

**Запасной путь без `npm link`.** Вместо `sv` везде пиши `node bin/sv.mjs`, находясь в папке `svyazka`. Например, `node bin/sv.mjs --help`. Всё остальное в инструкции работает так же.

## Шаг 6. Посмотри на пример

В проекте лежит вымышленная команда из пяти человек. На ней удобно понять, что к чему.

```bash
sv roster --dir examples/demo --today 2026-11-13
sv map --dir examples/demo --today 2026-11-13
sv signals --dir examples/demo --today 2026-11-13
sv sheet mark --dir examples/demo --today 2026-11-13
```

- `--dir` говорит, какую папку игры читать.
- `--today` показывает состояние на заданную дату. Пример собран под 13 ноября 2026 года; без этого флага все данные в нём будут выглядеть устаревшими.

Теперь то же самое в браузере:

```bash
sv web --dir examples/demo --today 2026-11-13
```

Кроме `demo`, в папке `examples` есть ещё пять команд: от «всё очень хорошо» (`kak-po-maslu`) до «всё очень плохо» (`this-is-fine`). Подставь имя папки вместо `demo`; список и описания — в `examples/README.md`.

Терминал напишет `Связка: http://127.0.0.1:4173` и останется «занятым» — так и должно быть, это работает сервер. Открой этот адрес в браузере.

Чтобы остановить сервер, вернись в терминал и нажми Ctrl+C.

> В примере лучше только смотреть. Если начать в нём ход, файлы примера изменятся. Вернуть их можно командой `git checkout examples`.

## Шаг 7. Создай свою папку игры

Папка игры должна лежать **отдельно от папки проекта**, не внутри `svyazka`.

| Система | Команда |
|---|---|
| Windows | `sv init $HOME\svyazka-game` |
| macOS и Linux | `sv init ~/svyazka-game` |

Команда задаст вопросы: как тебя зовут, твоя роль, ближайшая веха и кто в команде. Про каждого человека спросит имя, короткий идентификатор латиницей (предложит сама, например `anya` для «Аня») и роль. Чтобы закончить список людей, оставь имя пустым и нажми Enter.

В конце появится `Папка игры создана` и подсказка, что делать дальше. Внутри папки лежит `README.md` с примерами, как дописать навыки людей и добавить переходы.

Если Git ответил, что не знает, кто ты, выполни один раз и создай папку заново в другом месте:

```bash
git config --global user.name "Твоё имя"
git config --global user.email "ты@example.com"
```

## Шаг 8. Запомни путь к папке

Чтобы не писать `--dir` в каждой команде, запиши путь в переменную `SVYAZKA_DIR`.

**Windows (PowerShell):**

```powershell
[Environment]::SetEnvironmentVariable('SVYAZKA_DIR', "$HOME\svyazka-game", 'User')
```

**macOS:**

```bash
echo 'export SVYAZKA_DIR="$HOME/svyazka-game"' >> ~/.zshrc
```

**Linux:**

```bash
echo 'export SVYAZKA_DIR="$HOME/svyazka-game"' >> ~/.bashrc
```

Закрой терминал и открой заново. Проверка: `sv roster` без `--dir` показывает твою команду.

## Шаг 9. Первый день

```bash
sv turn start                            # спросит, сколько сил на сегодня
sv signals                               # на что стоит потратить внимание
sv map                                   # карта: где отряд, какая местность впереди
sv sheet anya                            # открыть лист: −1 внимания, один раз в день на человека
sv 1on1 anya --note "О чём говорили"     # −2, обновит дату встречи и журнал
sv decide "Что решил и почему"           # строка в журнал решений
sv turn                                  # как идёт день
sv turn end                              # что не успел, запись дня в историю
```

Вместо `anya` подставь идентификатор своего человека. Их показывает `sv roster` в первом столбце.

В новой папке `sv signals` сразу покажет предупреждения по каждому человеку: встреч ещё не было, листы не обновлялись. Это честное начальное состояние. Оно уходит по мере того, как ты проводишь встречи и заполняешь листы.

То же самое в браузере:

```bash
sv web
```

Открой http://127.0.0.1:4173. Ход начинается кнопкой в правом верхнем углу. Страница сама обновляется, когда файлы в папке игры меняются.

## Шаг 10. Штурман

Штурман — модель, которая отвечает на вопросы по данным твоей игры. Он только читает: в папке игры ничего не меняет. Без него всё остальное работает как раньше, так что этот шаг можно отложить.

### 10.1. Получи ключи

Нужен ключ хотя бы одной модели. Ключ — длинная строка, по которой поставщик понимает, с чьего счёта списывать деньги.

| Модель | Где взять ключ | Что важно |
|---|---|---|
| Claude | https://platform.claude.com → Settings → API keys → Create key | Ключ начинается с `sk-ant-` и показывается один раз. Счёт отдельный от подписки claude.ai: баланс пополняется в самой консоли |
| Kimi | https://platform.kimi.ai → API Keys | Нужен положительный баланс. Бери ключ на международной площадке: ключи с `platform.moonshot.cn` к ней не подходят |

### 10.2. Положи ключи в файл

```bash
sv keys init
```

Команда создаст файл ключей в домашней папке и напишет, чем его открыть:

| Система | Где лежит файл |
|---|---|
| Windows | `C:\Users\<ты>\.svyazka\keys.env` |
| macOS и Linux | `~/.svyazka/keys.env` |

Открой файл и впиши ключи после знака «=», без кавычек и пробелов:

```
ANTHROPIC_API_KEY=sk-ant-...
MOONSHOT_API_KEY=sk-...
```

Сохрани и закрой. Строку с пустым значением можно оставить: модель без ключа просто будет недоступна.

> Файл ключей лежит только на твоей машине. Не клади его в репозиторий и в папку игры, не присылай ключи в чаты. Если ключ куда-то утёк, отзови его в консоли поставщика и создай новый.

### 10.3. Проверь

```bash
sv keys            # какие ключи найдены; сами ключи не печатаются
sv keys --check    # пробный запрос к каждой модели
```

Во втором случае напротив каждой модели должно быть слово «отвечает». Если там ошибка, она написана по-русски: ключ не подошёл, нет денег на счёте, нет связи.

### 10.4. Спроси

```bash
sv ask "С кем поговорить первым?"
sv ask "Что мешает дойти до лагеря?" --model kimi
sv prep anya                              # заметки к 1on1 с человеком
```

Ответ приходит через 5–60 секунд. Первая строка говорит, какая модель отвечала и какие слои данных ей ушли, последняя — какие данные игры она смотрела.

В браузере штурман живёт на экране «отряд» (строка внизу) и на листе человека — кнопка «заметки к встрече от штурмана». Модель переключается кнопками `claude` и `kimi`; модель без ключа выбрать нельзя.

### 10.5. Если папка игры создана раньше

В старом `config.yaml` записана одна модель. Он продолжит работать, но только с Claude. Чтобы добавить Kimi, замени в `config.yaml` раздел `navigator` целиком:

```yaml
navigator:
  default: claude         # какая отвечает, если не указать --model
  models:                 # layers — какие слои можно отправлять этой модели
    claude: {provider: anthropic, model: claude-sonnet-5-5, layers: [team, pair, me]}
    kimi: {provider: moonshotai, model: kimi-k3, layers: [team, pair, me]}
```

### 10.6. Что уходит в облако

Модель получает только те слои, которые перечислены у неё в `layers`:

- `team` — то, что видит отряд: люди, ремесло, переходы, карта;
- `pair` — листы и журналы встреч;
- `me` — твои заметки на полях, связи и ходы.

По умолчанию обеим моделям открыто всё. Если не хочешь, чтобы записи о людях уходили какому-то поставщику, оставь ему `layers: [team]`: штурман ответит по открытым данным и скажет, чего ему не хватило.

## Как править данные

Файлы в папке игры — обычный текст. Открывай их любым редактором.

Удобнее всего Obsidian: «Open folder as vault» → выбери папку игры. Листы людей и журналы встреч станут обычными заметками.

После правок выполни `sv roster`. Если в файле ошибка, команда назовёт файл и поле, например:

```
team/tasks/billing.md: terrain: Invalid option: expected one of "trail"|"pass"|"fog"|"storm"
```

## Как обновить проект

Когда в репозитории появятся новые шаги:

```bash
cd svyazka
git pull
npm install
```

Папку игры это не затрагивает.

## Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| `node` или `git` не найдены | Вернись к шагу 2. После установки открой терминал заново |
| Версия Node.js меньше 22 | Поставь свежую LTS с nodejs.org поверх старой |
| `npm error` при `npm install` | Проверь интернет и повтори. Если не помогло, удали папку `node_modules` и повтори |
| `sv` не найдена | Шаг 5, раздел «Если не получилось» |
| «Папка игры не прошла проверку» | Ниже этой строки список: файл и что в нём не так. Исправь и повтори |
| «Ход на … не начат» | Сначала `sv turn start` |
| «Папка … не пуста» при `sv init` | Укажи другой путь: команда не затирает существующее |
| «Коммит пропущен» при `sv turn end` | Папка игры не является своим репозиторием. Создай её через `sv init` или выполни в ней `git init` |
| Порт 4173 занят | Запусти на другом: `sv web --port 4180` |
| «Нет ключа …» | Шаг 10.2: `sv keys init` и впиши ключ в файл |
| «Ключ … не подошёл» | Скопируй ключ заново, целиком. Для Kimi проверь, что он с международной площадки |
| «Поставщик отказал в доступе (403)» | У ключа нет прав на эту модель, либо поставщик не работает с твоим регионом или сетью |
| «Превышен лимит или исчерпан баланс» | Пополни счёт в консоли поставщика |
| «Модели … нет в настройках штурмана» | Шаг 10.5: добавь модель в `config.yaml` |
| Kimi отвечает очень долго | `kimi-k3` всегда рассуждает перед ответом. Замени в `config.yaml` модель на `kimi-k2.6` |
| Страница в браузере не открывается | Проверь, что терминал с `sv web` не закрыт и адрес набран точно: `http://127.0.0.1:4173` |

## Что проверено

- **Linux:** все шаги пройдены вручную.
- **Windows и macOS:** после каждой отправки в `main` автоматически запускаются полная проверка и те же команды, что в этой инструкции: `npm link`, `sv --help`, `sv init`, ход от начала до конца и запуск веб-сервера. Состояние видно на вкладке Actions в репозитории.
- **Не проверено автоматически:** установка Node.js и Git, вопросы `sv init` в настоящем окне PowerShell и работа с Obsidian.
- **Штурман** проверен на подставной модели: какие данные ей уходят, как выбирается модель, что показывают команды и страница. Запросов к настоящим Claude и Kimi в проверке нет: для них нужны твои ключи.
