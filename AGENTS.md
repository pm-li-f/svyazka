# Правила для агентов, которые строят «Связку»

«Связка» — внутренний инструмент CPTO: управление небольшой IT-командой в форме игры, где отряд — это команда. Полные решения по концепту и архитектуре лежат в проекте Claude «cpto rpg» (документы `cpto-rpg-decisions.md` и `cpto-rpg-architecture.md`). Здесь — то, что нужно знать, чтобы писать код.

## Команды

```bash
npm install
npm run check                          # типы, тесты и проверка примера — запускать перед каждым коммитом
npm run validate -- путь/к/папке/игры  # проверить папку с данными
node bin/sv.mjs roster --dir examples/demo --today 2026-11-13   # «Связка» в терминале; --help — все команды
node bin/sv.mjs web --dir examples/demo --today 2026-11-13      # веб-интерфейс на http://127.0.0.1:4173
node bin/sv.mjs map --dir examples/demo --today 2026-11-13         # карта и стратегия в терминале
node bin/sv.mjs keys --dir examples/demo                           # какие ключи моделей найдены
node bin/sv.mjs init /tmp/game --yes                            # новая папка игры без вопросов
npm run manual -- --publish                                     # пересобрать руководство игрока в docs/svyazka-manual.pdf — только по просьбе владельца
```

## Устройство

- `packages/core` — схема данных (`src/schema.ts`), загрузчик папки игры (`src/load.ts`) и запись в неё (`src/write.ts`). Запись правит только YAML-шапку: заметки под ней и комментарии сохраняются.
- `packages/engine` — движок: давность, линтер RACI, покрытие навыков, сигналы, правила хода и внимания, карта (`src/map.ts`: раскладка маршрута и переходов, рельеф, стратегия), события игрового слоя (`src/facts.ts` — снимок фактов, `src/events.ts` — что произошло между двумя снимками и что из этого показывать при данных настройках). Только чистые функции от состояния игры и даты; текущую дату движок сам не берёт.
- `packages/ops` — операции над папкой игры: прочитать, применить правило движка, записать. Возвращают данные; ими пользуются и `sv`, и веб.
- `packages/sources` — чтение Jira и Confluence Data Center: вход (`http.ts`: токен, логин и пароль в запросе, запасной вход по сессии), запросы (`jira.ts`, `confluence.ts`), сбор снимка (`sync.ts`), команды целиком (`run.ts`). Подставной сервер для тестов — `test/fake.ts`.
- `packages/navigator` — штурман: ключи (`keys.ts`), выбор и открытие модели (`models.ts`), инструменты игры для модели (`tools.ts`), правила (`prompt.ts`), вопрос и заметки к 1on1 (`ask.ts`).
- `packages/cli` — команда `sv`: отряд, карта, сигналы, RACI, навыки, лист, ход. Отрисовка — чистые функции, возвращающие текст; цвет накладывается отдельно и не влияет на ширину.
- `apps/web` — веб-интерфейс: `server/` — локальный сервер с API поверх `ops` и движка, `src/` — экраны на React, `src/game/` — игровой слой: заставки (`Splash.tsx`, кадр рисует `scene.ts`), эффекты (`Effects.tsx`), настройки игрока (`settings.ts`), звук (`sound.ts`). Сервер слушает только 127.0.0.1.
- `docs/manual` — руководство игрока: текст (`manual.md`), описания блоков экранов (`screens.ts`), пример хода (`story.ts`) и сборщик, который сам снимает экраны и печатает PDF. Готовый PDF — `docs/svyazka-manual.pdf`. Порядок обновления — в `docs/manual/README.md`.
- `examples/demo` — пример данных: вымышленная команда из пяти человек и двух агентов. На нём идут тесты.
- `examples/<другие>` — пять сценариев для показа: два крайних и три про отдельные стороны игры (список в `examples/README.md`). Что именно должен показывать каждый, закреплено в `packages/engine/test/examples.test.ts`: меняешь данные или правила — сверяйся с ним.
- Представления для экранов (`sheetView`, `raciMatrix`, `skillMatrix`) живут в движке: интерфейс получает уже отфильтрованные по слою данные и сам ничего не скрывает.

## Инварианты, которые нельзя ломать

1. **Слой видимости — это папка.** `team/` видит отряд, `pair/` — человек и CPTO, `me/` — только CPTO. Данные не переезжают между слоями без явного решения в схеме.
2. **Схема — источник правды.** Формат меняется сначала в `schema.ts`, потом в примере, потом в коде. Неизвестные поля — ошибка.
3. **Слой нельзя показать случайно.** Любой вывод о человеке принимает слой, до которого показывать (`team`, `pair`, `me`), и на это есть тесты: вид отряда не содержит ничего из слоёв пары и CPTO.
4. **У каждого факта есть дата**, а где важно — и автор. Без этого не посчитать давность.
5. **Загрузчик проверяет форму и ссылки, движок — смысл.** RACI без ответственного или с агентом в роли A — валидные данные, которые ловит линтер, а не ошибка загрузки.
6. **Агент может быть R, но не A.** За каждого агента отвечает человек.
7. **Секреты не лежат в репозитории и в папке игры.** Ключи моделей, логин и пароль к Jira и Confluence — в переменных окружения или в файле `~/.svyazka/keys.env` в домашней папке. Адрес сервера с логином внутри (`https://user:pass@…`) схема не принимает. Значение ключа не печатается нигде: ни в выводе, ни в ошибках, ни в ответе API.
8. **Интеграции только на чтение.** Jira (версия ниже 8.14, REST API v2, вход по логину и паролю отдельной учётной записи) и Confluence оформляются как отдельные серверы инструментов (MCP).
9. **Игра — зеркало, а не турникет.** Перерасход внимания разрешён и просто показывается. Сигнал снимается только изменением данных, а не отметкой «разобрано».
10. **Коммит хода — только в корне своего репозитория.** Если папка игры лежит внутри чужого репозитория, коммит пропускается.
11. **Веб отвечает только своей странице.** Сервер слушает 127.0.0.1, проверяет Host и Origin, запись принимает только с заголовком `x-svyazka` и JSON. Новые адреса API проходят через ту же проверку.
12. **Карту не рисуют, а считают.** `mapView` — чистая функция от состояния и даты, без `Math.random` и без текущего времени: одно состояние — одна карта на любой машине. Она читает только слой `team`. Каждое пятно на карте объясняется данными; украшений, за которыми ничего не стоит, не добавляем.
13. **Штурман — сменный слой** на Vercel AI SDK. Поставщики подключаются напрямую своими ключами, без общего шлюза. Какие слои уходят модели, задаёт её `layers` в `config.yaml`.
14. **Закрытый слой не доходит до модели.** Все инструменты штурмана считаются по игре, из которой закрытые слои вырезаны (`capGame`), а не фильтруют ответ после. Новый инструмент обязан идти тем же путём, и на это есть тест: строки из закрытых слоёв не встречаются ни в одном запросе к модели.
15. **Штурман только читает.** Инструментов, которые пишут в папку игры, у модели нет. Ответ модели — не факт игры: он показывается, но в листы и журналы сам не попадает.
16. **Каждый ответ подписан:** какая модель, какие слои ей ушли, какие инструменты она вызывала.
17. **Игровой слой ничего не решает и ничего не пишет.** Заставки и эффекты — только показ: в папку игры они не пишут, правил не меняют, и с выключенными настройками игра та же. Настройки у каждого игрока свои и живут в его браузере.
18. **Эффект бывает только за то, что закрылось.** Что считается событием, решает одна функция — `events` в `packages/engine/src/events.ts`: разница двух снимков фактов. Экран сам событий не выдумывает и по кнопкам их не запускает, поэтому правка файла в редакторе и кнопка дают одно и то же. Список «чего в игре нет» ниже закреплён там же тестами; новое событие добавляется туда и проходит через `plan`, который гасит эффекты в шторм.
19. **Движение и звук — по согласию.** `prefers-reduced-motion` соблюдается: заставка — один неподвижный кадр, эффекты без искр. Звук выключен, пока игрок его не включил. Вспышек на весь экран нет. Заставка пропускается любой клавишей.
20. **Источники только читаются.** Соединение из `packages/sources` умеет один метод данных — GET. Единственное исключение — вход и выход по сессии Jira. Писать в Jira и Confluence игра не должна уметь вообще; на это есть тест по журналу запросов подставного сервера.
21. **Движок в сеть не ходит.** Данные источников попадают в игру одним путём: `sv sync` пишет снимок в `team/sources/`, движок считает по нему. Сроки отсчитываются от даты снимка, устаревший снимок назван устаревшим. Источник, который не ответил, прежний снимок не стирает.
22. **В игре переходы, а не тикеты.** Связь с Jira — только по ссылке, записанной руками. Переходы из эпиков сами не заводятся.
23. **Число задач — не оценка человека.** Нагрузка из Jira показывается порогом на собственное число, без сравнения людей и без сортировки по нему.
24. **Источники для моделей закрыты, пока не открыты.** У модели в `config.yaml` свой список `sources`, с начала пустой. Закрытый снимок вырезается в `capGame` вместе с настройкой источника — до инструментов. Напрямую к Jira и Confluence штурман не ходит.

## Чего в игре нет по решению

- Наград за израсходованный бюджет внимания и за число проведённых 1on1.
- Эффектов на оценках людей и во время шторма.
- Серий («N дней подряд») и сравнений между людьми.
- Баллов за стрессоустойчивость: это состояние, человек описывает его словами.
- Баллов в 360: только темы текстом.

## Соглашения

- TypeScript в строгом режиме, модули ESM.
- Идентификаторы в коде и в данных — латиницей; тексты для людей — по-русски.
- Каждое новое поведение покрывается тестом на `examples/demo` или на его изменённой копии.
- Числа-прикидки (срок годности, потолок внимания) живут в `config.yaml`, не в коде.
- Источники в тестах работают на подставном сервере (`packages/sources/test/fake.ts`); в сеть тесты не ходят и настоящего файла ключей не читают. Снимки примера `examples/jira-pomnit-vse` должны совпадать с тем, что `sv sync` снимает с подставного сервера, — на это есть тест; меняешь данные сервера — пересними пример.
- Штурман в тестах работает на подставной модели (`MockLanguageModelV4` из `ai/test`); в сеть тесты не ходят и настоящих ключей не читают.
- **Руководство игрока обновляется только по явной просьбе владельца.** `docs/svyazka-manual.pdf` и исходники в `docs/manual` при обычной работе над игрой не трогаем, даже если экраны изменились: на обложке указано, какую версию оно описывает. Когда попросят обновить — порядок в `docs/manual/README.md`. Новым блокам экрана всё равно давай `data-block`: по нему их найдёт следующая сборка.
- Длинный список на экране живёт в окне с прокруткой (`Scroll` или `.scroll-x.cap`), а не растягивает страницу.
- Проект должен работать на Windows, macOS и Linux: пути собираются через `node:path`, внешние программы запускаются без оболочки, в сообщениях путь пишется через «/». CI (`.github/workflows/check.yml`) гоняет проверку и дымовой сценарий на всех трёх; меняешь команды запуска — обнови и его, и `docs/kak-zapustit.md`.

## План сборки

| Шаг | Что делаем | Готово, когда |
|---|---|---|
| 0 | Скелет, схема данных, пример | `npm run check` зелёный — **сделано** |
| 1 | Движок: давность, сигналы, линтер RACI, покрытие навыков | На примере получаются сигналы из макета: держит один, протухший контекст, отвечает агент, никто не ведёт — **сделано** |
| 2 | Команда `sv`: отряд, RACI, навыки, лист | Экраны макета читаются в терминале — **сделано** |
| 3 | Ход и внимание: утренняя отметка, списание, журнал, коммит в конце хода | Можно прожить день в терминале и Obsidian — **сделано** |
| 4 | Веб-интерфейс: отряд, лист, переходы | Экраны совпадают с макетами v2 — **сделано**, плюс экран хода |
| 5 | Карта: рельеф генерируется из состояния | Экран стратегии — **сделано**, плюс `sv map` |
| 6 | Штурман: AI SDK, инструменты игры, заметки к 1on1 | Строка штурмана отвечает по данным — **сделано** на подставной модели; с настоящими Claude и Kimi проверяет владелец ключей |
| 7 | Интеграция с Jira на чтение, затем Confluence | Данные из источников попадают в сигналы — **сделано** на подставном сервере; на настоящих Jira 11 и Confluence 8.7 проверяет владелец. Отдельный сервер инструментов (MCP) для источников перенесён в шаг 8 |
| 8 | Сервер инструментов игры, слово агентам | Агент оставляет отчёт через инструмент |
| 9 | Черновики артефактов: риски, план коммуникаций, отчёт инвесторам | Черновик собирается из журнала ходов |
| 10 | Заставки и эффекты с настройками | Игровой слой отключается настройкой — **сделано** (раньше шагов 7–9 по просьбе владельца) |
