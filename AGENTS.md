# Правила для агентов, которые строят «Связку»

«Связка» — внутренний инструмент CPTO: управление небольшой IT-командой в форме игры, где отряд — это команда. Полные решения по концепту и архитектуре лежат в проекте Claude «cpto rpg» (документы `cpto-rpg-decisions.md` и `cpto-rpg-architecture.md`). Здесь — то, что нужно знать, чтобы писать код.

## Команды

```bash
npm install
npm run check                          # типы, тесты и проверка примера — запускать перед каждым коммитом
npm run validate -- путь/к/папке/игры  # проверить папку с данными
node bin/sv.mjs roster --dir examples/demo --today 2026-11-13   # «Связка» в терминале; --help — все команды
node bin/sv.mjs web --dir examples/demo --today 2026-11-13      # веб-интерфейс на http://127.0.0.1:4173
node bin/sv.mjs map --dir examples/demo --today 2026-11-13         # карта и стратегия в терминале
node bin/sv.mjs init /tmp/game --yes                            # новая папка игры без вопросов
```

## Устройство

- `packages/core` — схема данных (`src/schema.ts`), загрузчик папки игры (`src/load.ts`) и запись в неё (`src/write.ts`). Запись правит только YAML-шапку: заметки под ней и комментарии сохраняются.
- `packages/engine` — движок: давность, линтер RACI, покрытие навыков, сигналы, правила хода и внимания, карта (`src/map.ts`: раскладка маршрута и переходов, рельеф, стратегия). Только чистые функции от состояния игры и даты; текущую дату движок сам не берёт.
- `packages/ops` — операции над папкой игры: прочитать, применить правило движка, записать. Возвращают данные; ими пользуются и `sv`, и веб.
- `packages/cli` — команда `sv`: отряд, карта, сигналы, RACI, навыки, лист, ход. Отрисовка — чистые функции, возвращающие текст; цвет накладывается отдельно и не влияет на ширину.
- `apps/web` — веб-интерфейс: `server/` — локальный сервер с API поверх `ops` и движка, `src/` — экраны на React. Сервер слушает только 127.0.0.1.
- `examples/demo` — пример данных: вымышленная команда из пяти человек и двух агентов. На нём идут тесты.
- `examples/<другие>` — пять сценариев для показа: два крайних и три про отдельные стороны игры (список в `examples/README.md`). Что именно должен показывать каждый, закреплено в `packages/engine/test/examples.test.ts`: меняешь данные или правила — сверяйся с ним.
- Представления для экранов (`sheetView`, `raciMatrix`, `skillMatrix`) живут в движке: интерфейс получает уже отфильтрованные по слою данные и сам ничего не скрывает.

## Инварианты, которые нельзя ломать

1. **Слой видимости — это папка.** `team/` видит отряд, `pair/` — человек и CPTO, `me/` — только CPTO. Данные не переезжают между слоями без явного решения в схеме.
2. **Схема — источник правды.** Формат меняется сначала в `schema.ts`, потом в примере, потом в коде. Неизвестные поля — ошибка.
3. **Слой нельзя показать случайно.** Любой вывод о человеке принимает слой, до которого показывать (`team`, `pair`, `me`), и на это есть тесты: вид отряда не содержит ничего из слоёв пары и CPTO.
4. **У каждого факта есть дата**, а где важно — и автор. Без этого не посчитать давность.
5. **Загрузчик проверяет форму и ссылки, движок — смысл.** RACI без ответственного или с агентом в роли A — валидные данные, которые ловит линтер, а не ошибка загрузки.
6. **Агент может быть R, но не A.** За каждого агента отвечает человек.
7. **Секреты не лежат в репозитории и в папке игры.** Ключи моделей и пароль Jira — в связке ключей системы или в переменных окружения.
8. **Интеграции только на чтение.** Jira (версия ниже 8.14, REST API v2, вход по логину и паролю отдельной учётной записи) и Confluence оформляются как отдельные серверы инструментов (MCP).
9. **Игра — зеркало, а не турникет.** Перерасход внимания разрешён и просто показывается. Сигнал снимается только изменением данных, а не отметкой «разобрано».
10. **Коммит хода — только в корне своего репозитория.** Если папка игры лежит внутри чужого репозитория, коммит пропускается.
11. **Веб отвечает только своей странице.** Сервер слушает 127.0.0.1, проверяет Host и Origin, запись принимает только с заголовком `x-svyazka` и JSON. Новые адреса API проходят через ту же проверку.
12. **Карту не рисуют, а считают.** `mapView` — чистая функция от состояния и даты, без `Math.random` и без текущего времени: одно состояние — одна карта на любой машине. Она читает только слой `team`. Каждое пятно на карте объясняется данными; украшений, за которыми ничего не стоит, не добавляем.
13. **Штурман — сменный слой** на Vercel AI SDK. Поставщики подключаются напрямую своими ключами, без общего шлюза. Какие слои уходят в модель, задаёт `navigator.cloud_layers`.

## Чего в игре нет по решению

- Наград за израсходованный бюджет внимания и за число проведённых 1on1.
- Эффектов на оценках людей и во время шторма.
- Серий («N дней подряд») и сравнений между людьми.
- Баллов за стрессоустойчивость: это состояние, человек описывает его словами.
- Баллов в 360: только темы текстом.

## Соглашения

- TypeScript в строгом режиме, модули ESM.
- Идентификаторы в коде и в данных — латиницей; тексты для людей — по-русски.
- Каждое новое поведение покрывается тестом на `examples/demo` или на его изменённой копии.
- Числа-прикидки (срок годности, потолок внимания) живут в `config.yaml`, не в коде.
- Проект должен работать на Windows, macOS и Linux: пути собираются через `node:path`, внешние программы запускаются без оболочки, в сообщениях путь пишется через «/». CI (`.github/workflows/check.yml`) гоняет проверку и дымовой сценарий на всех трёх; меняешь команды запуска — обнови и его, и `docs/kak-zapustit.md`.

| Шаг | Что делаем | Готово, когда |
|---|---|---|
| 0 | Скелет, схема данных, пример | `npm run check` зелёный — **сделано** |
| 1 | Движок: давность, сигналы, линтер RACI, покрытие навыков | На примере получаются сигналы из макета: держит один, протухший контекст, отвечает агент, никто не ведёт — **сделано** |
| 2 | Команда `sv`: отряд, RACI, навыки, лист | Экраны макета читаются в терминале — **сделано** |
| 3 | Ход и внимание: утренняя отметка, списание, журнал, коммит в конце хода | Можно прожить день в терминале и Obsidian — **сделано** |
| 4 | Веб-интерфейс: отряд, лист, переходы | Экраны совпадают с макетами v2 — **сделано**, плюс экран хода |
| 5 | Карта: рельеф генерируется из состояния | Экран стратегии — **сделано**, плюс `sv map` |
| 6 | Штурман: AI SDK, инструменты игры, заметки к 1on1 | Строка штурмана отвечает по данным |
| 7 | Интеграция с Jira на чтение, затем Confluence | Данные из источников попадают в сигналы |
| 8 | Сервер инструментов игры, слово агентам | Агент оставляет отчёт через инструмент |
| 9 | Черновики артефактов: риски, план коммуникаций, отчёт инвесторам | Черновик собирается из журнала ходов |
| 10 | Заставки и эффекты с настройками | Игровой слой отключается настройкой |
